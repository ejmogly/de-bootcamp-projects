Airflow 3.0 & Datasets

고정된 스케줄에 의존하던 전통적인 크론(Cron) 배치 방식에서 벗어나, 데이터 생성 이벤트(Dataset)에 즉각 반응하고 가변적인 입력 파티션을 동적으로 병렬 처리(Dynamic Task Mapping)하는 차세대 오케스트레이션 아키텍처를 구축했습니다.

🚨 기존 오케스트레이션의 한계 (Pain Points)
  • 고정 스케줄 지연: 선행 배치가 끝나지 않았는데 다음 배치가 돌아 중복/누락 발생.
  • 정적 태스크의 경직성: 처리할 파일 수가 매일 다른데 태스크 수가 고정되어 병렬 확장 불가.
  • 보일러플레이트 코드 폭증: 기존 Operator 방식의 장황한 클래스 선언과 복잡한 XCom 매핑.
💡 Airflow 3.0 엔지니어링 해결책 (Solutions)
  • TaskFlow API (@dag, @task): 파이썬 데코레이터 기반으로 비즈니스 로직에만 집중하는 직관적 DAG 개발.
  • Dynamic Task Mapping: 런타임에 결정되는 파일 리스트에 따라 태스크를 동적으로 생성하여 100% 병렬 처리.
  • Data-driven Datasets: 시간 기반 스케줄링 대신 S3 데이터셋 생성 이벤트에 반응하는 반응형(Reactive) 파이프라인 완성.
  • AWS Athena 연동: AthenaHook을 통해 S3 데이터 카탈로그 등록 및 SQL 분석 쿼리 자동화.
