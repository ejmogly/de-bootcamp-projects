문제 4

목표

  • 제공된 sensor_logs.csv (공장 생산라인 센서 로그 5만건)를 Spark로 읽어 Parquet 포맷으로 변환 후 S3에 파티션 저장합니다.

주요 요구사항 및 구현 상세

1. 스키마 직접 정의 (inferSchema 사용 금지)

  • StructType + StructField로 스키마 정의
  • machine_id → StringType
  • timestamp → TimestampType
  • temperature, vibration, pressure → DoubleType
  • status → StringType
  • 로딩 후 printSchema() 출력 — 타입이 위와 일치해야 함
  • df.show(5) 출력

2. 날짜 컬럼 추가

  • withColumn("date", to_date(col("timestamp")))으로 날짜 컬럼 추가
  • 추가 후 df.show(3)으로 date 컬럼 확인

3. Parquet 변환 + S3 파티션 저장 (멱등성 보장)

  • 저장 경로: s3a://버킷명/sensor/parquet/ (s3a:// 스킴 필수)
  • partitionBy("machine_id", "date") 적용
  • mode("overwrite") 적용 — 재실행 시 중복 적재 방지

4. 저장 확인 (필수)

  • boto3.list_objects_v2()로 저장된 파일 목록 출력
  • 출력에 Key, LastModified, Size 3가지 반드시 포함
  • ※ LastModified = AWS가 자동으로 기록하는 업로드 시각 (실제 실행 증빙)

5. 멱등성 검증 (필수)

  • 동일 코드를 2회 실행한 뒤 각각 spark.read.parquet(...).count() 출력
  • 1회차 count와 2회차 count가 동일한지 확인
  • 왜 동일하게 유지되는지 1줄 서술

채점 기준

  • O: StructType 정의(타입 일치) + partitionBy + mode("overwrite") + s3a:// + Key/LastModified/Size 출력 + 1·2회차 count 동일 캡처 + 서술
  • X: inferSchema=True 사용 (StructType 미사용)
  • X: s3a:// 스킴 미사용
  • X: S3 저장 확인 출력에 LastModified 없음
  • X: partitionBy("machine_id", "date") 미사용
  • X: 멱등성 캡처 미제출 (1·2회차 count 비교 없음)
  • X: 서술 없음

제출물 체크리스트

  1. ⏳ 코드 (AWS 키는 '' 빈 문자열로)
  2. ⏳ printSchema() + show(5) 캡처
  3. ⏳ S3 저장 확인 출력 캡처 — 아래 형식으로 나오면 성공: text Key: sensor/parquet/machine_id=M001/date=2024-01-01/part-00000.parquet LastModified: 2026-06-24 11:21:03+00:00 Size: 12480 bytes
  4. ⏳ 멱등성 검증 캡처 — 아래 형식으로 나오면 성공: text 1회차 row count: 50000 2회차 row count: 50000 동일 여부: True
  5. ⏳ mode("overwrite")가 멱등성을 보장하는 이유 1줄 서술

문제 5

목표

  • Q4에서 S3에 저장한 Parquet 파일을 로딩하여 Window Function으로 설비별 이상 징후를 탐지합니다.

주요 요구사항 및 구현 상세

1. S3 Parquet 로딩

  • Q4에서 저장한 s3a://버킷명/sensor/parquet/ 경로에서 로딩
  • 로딩 후 총 row count 출력

2. Window 정의

  • 설비별 시간순 정렬 윈도우: Window.partitionBy("machine_id").orderBy("timestamp")
  • 설비별 vibration 내림차순 윈도우: Window.partitionBy("machine_id").orderBy(col("vibration").desc())
  • 설비별 누적 윈도우: rowsBetween(Window.unboundedPreceding, 0)

3. 아래 3가지 윈도우 집계 수행

  • temp_moving_avg: avg("temperature").over(rowsBetween(-9, 0)) — 현재 포함 직전 10개 행 이동평균
  • vibration_rank: rank().over(vibration 내림차순 윈도우) — 설비 내 진동 순위
  • error_cumsum: sum(when(status=="오류", 1).otherwise(0)).over(누적 윈도우) — 누적 오류 건수

4. 이상 감지 필터 + 출력

  • 조건: temp_moving_avg > 85 OR vibration_rank <= 5
  • 필터 후 이상 감지 건수 출력
  • 결과 .show(20) 출력 (machine_id, timestamp, status, temp_moving_avg, vibration_rank, error_cumsum 포함)

채점 기준

  • O: 3개 컬럼(temp_moving_avg/vibration_rank/error_cumsum) 모두 존재 + 필터(>85 OR <=5) 적용 + 이상 감지 건수 + show(20) 캡처
  • X: 3개 Window 집계 중 하나라도 누락
  • X: rowsBetween 없이 전체 윈도우 평균 계산 (직전 10개 행 미적용)
  • X: 필터 조건(>85 OR <=5) 미적용
  • X: 이상 감지 건수 또는 show() 캡처 미제출

제출물 체크리스트

  • ⏳ 코드 (AWS 키는 '' 빈 문자열로)
  • ⏳ 이상 감지 건수 출력 캡처
  • ⏳ .show(20) 결과 캡처 (machine_id, timestamp, temp_moving_avg, vibration_rank, error_cumsum 컬럼 포함)

문제 6

목표

  • sensor_logs와 equipment (설비 마스터)를 Broadcast Join으로 결합하여 공장별 불량률을 집계하고, 파티션 최적화 후 S3에 저장합니다.

주요 요구사항 및 구현 상세

1. 데이터 로딩

  • sensor_logs: Q4에서 저장한 s3a://버킷명/sensor/parquet/에서 로딩
  • equipment: 제공된 equipment.csv를 StructType으로 로딩 후 show() 출력

2. Broadcast Join

  • from pyspark.sql.functions import broadcast 임포트
  • join 전 df_logs.rdd.getNumPartitions() 출력
  • df_logs.join(broadcast(df_equip), "machine_id")로 join 수행
  • join 후 df_joined.rdd.getNumPartitions() 출력
  • ※ broadcast를 쓰는 이유: equipment는 설비 수가 적은 소규모 테이블 → 각 executor에 통째로 복사해 shuffle 없이 join

3. 공장별 불량률 집계

  • groupBy("factory")로 집계
  • total_logs: 전체 로그 수
  • error_count: status == '오류'인 건수
  • error_rate_pct: error_count / total_logs * 100 (소수점 2자리)
  • .show()로 결과 출력

4. 파티션 최적화 + S3 저장

  • df_joined.repartition(4) 적용 후 getNumPartitions() 출력
  • 집계 결과(df_factory)를 coalesce(1)로 줄인 후 S3에 CSV 저장
  • 저장 경로: s3a://버킷명/sensor/factory_error_rate/
  • boto3.list_objects_v2()로 저장 확인 (Key, LastModified, Size 포함)

5. 서술 (필수)

  • equipment에 broadcast를 적용한 이유를 1줄로 서술

채점 기준

  • O: broadcast() 사용 + 파티션 수 3회 출력(join 전/후/repartition) + total_logs/error_count/error_rate_pct 집계 + S3 저장 LastModified 출력 + 서술
  • X: broadcast() 미사용
  • X: 파티션 수 3회 출력 중 하나라도 캡처 없음
  • X: error_rate_pct(오류율) 컬럼 없음
  • X: S3 저장 확인 LastModified 없음
  • X: 서술 없음

제출물 체크리스트

  • ⏳ 코드 (AWS 키는 '' 빈 문자열로)
  • ⏳ 파티션 수 출력 캡처 — join 전 / join 후 / repartition(4) 후 3회 모두 포함
  • ⏳ 공장별 불량률 집계 결과 캡처 (factory, total_logs, error_count, error_rate_pct 컬럼)

주요 요구사항 및 구현 상세

2. Broadcast Join

  • from pyspark.sql.functions import broadcast 임포트
  • join 전 df_logs.rdd.getNumPartitions() 출력
  • df_logs.join(broadcast(df_equip), "machine_id")로 join 수행
  • join 후 df_joined.rdd.getNumPartitions() 출력
  • ※ broadcast를 쓰는 이유: equipment는 설비 수가 적은 소규모 테이블 → 각 executor에 통째로 복사해 shuffle 없이 join

3. 공장별 불량률 집계

  • groupBy("factory")로 집계
  • total_logs: 전체 로그 수
  • error_count: status == '오류'인 건수

  • .show()로 결과 출력

4. 파티션 최적화 + S3 저장

  • df_joined.repartition(4) 적용 후 getNumPartitions() 출력
  • 집계 결과(df_factory)를 coalesce(1)로 줄인 후 S3에 CSV 저장
  • 저장 경로: s3a://버킷명/sensor/factory_error_rate/
  • boto3.list_objects_v2()로 저장 확인 (Key, LastModified, Size 포함)

5. 서술 (필수)

  • equipment에 broadcast를 적용한 이유를 1줄로 서술

채점 기준

  • O: broadcast() 사용 + 파티션 수 3회 출력(join 전/후/repartition) + total_logs/error_count/error_rate_pct 집계 + S3 저장 LastModified 출력 + 서술
  • X: broadcast() 미사용
  • X: 파티션 수 3회 출력 중 하나라도 캡처 없음
  • X: error_rate_pct(오류율) 컬럼 없음
  • X: S3 저장 확인 LastModified 없음
  • X: 서술 없음
