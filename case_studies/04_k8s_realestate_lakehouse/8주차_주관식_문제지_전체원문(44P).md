과제 01 — 부동산 실거래가 Bronze (API 수집)

배점: 10 점

국토교통부 실거래가 공개 API 를 호출하여 다중 시군구의 아파트 매매 데이터를 수집하고, 원본 XML 을 그대로 AWS S3 bronze 영역에 저장하는 Airflow DAG 를 구현하세요. 본인이 직접 발급받은 data.go.kr API 키를 사용해야 합니다.

조건
• API 신청: data.go.kr/data/15126469/openapi.do (국토교통부_아파트 매매 실거래가 자료)
• End Point: https://apis.data.go.kr/1613000/RTMSDataSvcAptTrade/getRTMSDataSvcAptTrade
• 필수 파라미터: serviceKey, LAWD_CD (시군구코드 5 자리), DEAL_YMD (yyyyMM)
• DAG 이름: bronze_realestate_collect
• 스케줄: @monthly, catchup=True (월 단위)
• TaskGroup 또는 dynamic task mapping 으로 6 개 시군구(11680·11650·11710·11440·11170·11200) 병렬 수집
• BranchPythonOperator 로 응답 0 건/XML 파싱 실패 시 분기 처리
• S3 저장 경로: s3://realestate-홍길동/bronze/{yyyymm}/{LAWD_CD}.xml
• 수집 task 첫 줄에 print(f'collector={본인이름}, time={datetime.now()}, lawd={LAWD_CD}') 강제

배점: 10 점

과제 01 에서 적재한 raw XML 을 PySpark 로 파싱·정제하고, UDF 2 개로 평당가·평형 분류 컬럼을 생성한 뒤 parquet 으로 silver 영역에 저장하세요.

조건
• DAG 이름: silver_realestate_transform
• ExternalTaskSensor 로 과제 01 DAG(bronze_realestate_collect) 완료 대기
• (v2) Spark Job 실행은 SparkSubmitOperator 또는 BashOperator + spark-submit 으로 호출 (PythonOperator + python 실행 금지)
• spark-xml 또는 직접 XML 파싱으로 DataFrame 생성
• 결측치 (거래금액 / 면적 NULL) row 제거
• 거래금액 콤마·공백 제거 후 정수 변환
• 시군구별 IQR 1.5 배 밖 평당가 이상치 제거
• UDF (1) price_per_pyeong: 거래금액 ÷ (전용면적 ÷ 3.3058)
• UDF (2) size_category: 60 미만 소형 / 60~85 중소형 / 85~135 중대형 / 135 이상 대형
• 출력: parquet + snappy 압축, 파티션 키 = (시군구, yyyymm)
• S3 경로: s3://realestate-홍길동/silver/{시군구}/yyyymm=XXXXXX/

과제 04 — Airflow on Kubernetes (부동산 DAG 배포)

배점: 10 점

지금까지 부동산 DAG(과제 01 ~ 03)는 로컬 docker-compose 의 dags/ 폴더에 파일을 두는 방식으로 배포했습니다.
이번에는 Airflow 자체를 Kubernetes 위에 올리고, DAG 를 git-sync 방식으로 배포합니다.

실습 환경 — 로컬 Kubernetes 클러스터, 과제 09 의 EC2 + k3s 어느 쪽이든 무방합니다.
이 문항은 AWS 자격증명이 필요하지 않습니다.

조건
(1) helm 으로 Airflow 설치
• 차트는 apache-airflow/airflow, 버전 1.16.0 을 사용합니다.
• Namespace 는 airflow-{본인이름}으로 만들면서 설치합니다. (--create-namespace)
• 설치 명령과 완료 출력을 캡처하세요.

(2) values.yaml 작성
아래 항목을 반드시 포함합니다.
• dags.gitSync — enabled · repo · branch · subPath · depth · wait
  repo 는 본인 GitHub 레포지토리, subPath 는 DAG 를 담은 하위 폴더입니다.
• postgresql.enabled: true · postgresql.primary.persistence.enabled: false

(3) DAG 배포 — git-sync
• 본인 GitHub 레포지토리의 DAG 폴더에 아래 4 개를 올립니다.
  과제 01 ~ 03 의 DAG 3 개 (bronze_realestate_collect · silver_realestate_transform · gold_realestate_aggregate)
  git-sync 동작 확인용 테스트 DAG 1 개 — BashOperator 만 사용하는 간단한 DAG
• 파일을 레포에 push 한 뒤, Airflow UI 목록에 4 개가 모두 나타나는 것을 캡처합니다.
  로컬 dags/ 폴더에 파일을 두지 않았는데도 목록에 뜬다는 것이 곧 git-sync 가 동작했다는 증거입니다.

과제 06 — Redshift 적재 + Spectrum 조인 + 윈도우 분석

배점: 10 점

과제 05 의 silver parquet 를 Redshift 에 COPY 적재하고, stock_meta 를 Spectrum 외부 테이블로 얹어 조인·윈도우 분석을 수행하세요.

조건
• Redshift Serverless 워크그룹 생성 (별도 클러스터 프로비저닝 불필요)
• stock_prices 테이블 DDL 생성 (제공 스키마 준수)
• S3 silver → Redshift COPY 적재 (FORMAT AS PARQUET, INSERT 하드코딩 금지)
• stock_meta(S3)를 Redshift Spectrum external schema/table 로 등록
• 분석 쿼리 3 개 이상:
  (1) 종목별 평균종가·총거래량 (internal 테이블, GROUP BY)
  (2) stock_prices(internal) ⋈ stock_meta(external) 섹터별 평균 (Spectrum 조인)
  (3) lag(close) over(partition by ticker order by trade_date) 전일대비 등락 (윈도우 함수)
  (4) 위 3 번(윈도우 함수) 결과 전체 건수 COUNT(*) — 화면상 LIMIT 으로 일부만 보이더라도 전체 행수 검증용으로 별도 실행
• 모든 캡처는 Redshift 콘솔(Query Editor v2) 화면이어야 함 — CLI(psql, redshift-data 등) 터미널 캡처나 print() 출력문은 인증·연결 여부를 확인할 수 없어 인정하지 않음
• 비용 주의 — Serverless 는 쿼리를 실행하지 않으면 컴퓨트 과금이 0 이지만(RPU-초 단위), 적재한 데이터의 스토리지 과금은 계속 발생합니다.
  과제를 마친 뒤 워크그룹과 네임스페이스를 삭제해 두시길 권장합니다.

과제 08 — StatefulSet 으로 종목별 집계 결과 서빙

배점: 10 점

과제 05 의 주식 집계 결과는 S3 와 Redshift 에만 있습니다. 이번에는 클러스터 내부에 종목별로 데이터를 나눠 보관하고, StatefulSet 이 Deployment 와 무엇이 다른지를 직접 확인합니다.

Deployment 의 파드는 서로 대체 가능하지만, StatefulSet 의 파드는 각자 고유한 이름 · DNS · 볼륨을 가집니다.

실습 환경 — 강의에서 사용한 로컬 k3d 로 진행하면 됩니다. 이 문항은 AWS 자격증명이 필요하지 않습니다. 과제 05 의 집계 결과 수치만 옮겨 적으면 됩니다.

조건
(1) Namespace · Headless Service
• Namespace 는 stock-{본인이름} 으로 만듭니다.
  네임스페이스에 속하는 리소스(Service · StatefulSet 등)는 매니페스트에 metadata.namespace 를 명시하세요.
  채점자는 kubectl apply -f Q8/k8s/ 를 -n 없이 그대로 실행합니다.
• Headless Service 를 만듭니다.
  로드밸런싱 없이 각 파드의 DNS 이름이 직접 노출되도록 설정합니다.
  포트에 이름을 부여하세요. (StatefulSet 쪽과 같은 이름이어야 합니다)

(2) StatefulSet
• serviceName 은 (1)의 Headless Service 이름과 일치해야 합니다.
• replicas: 5 — 주식 데이터의 종목 수와 같습니다.
• 컨테이너는 nginx 계열 이미지를 사용하고, 컨테이너 포트 이름을 (1) 과 동일하게 지정합니다.
• volumeClaimTemplates 로 파드마다 볼륨을 따로 붙입니다.
