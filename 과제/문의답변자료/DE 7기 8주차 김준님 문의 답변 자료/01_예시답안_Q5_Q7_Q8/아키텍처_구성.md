# 과제 05 · 07 · 08 예시 답안 — 구성과 실행 방법

이 폴더는 과제 05 · 07 · 08을 운영 관점의 클린 코드로 작성한 예시 답안입니다. 문제지 조건을 충족하는 여러 구현 방식 중 하나입니다.
코드에는 버킷명·계정 번호를 넣지 않았고, 실행할 때 인자·환경 변수로 넘깁니다(`<본인버킷>`, `<ACCOUNT_ID>` 자리).
`stock-honggildong`, `홍길동`, `3기`는 문제지 예시 값입니다.

## 폴더 구성

```
01_예시답안_Q5_Q7_Q8/
├─ Q5/process_stocks.py          과제 05 정제·집계 (Q7 이 그대로 재사용하는 모듈)
├─ Q7/
│  ├─ Dockerfile                 apache/spark:3.5.7 + S3A jar + boto3, Q5·Q7 모듈 포함
│  ├─ spark_job.py               Q5 로직 재사용 → 집계 결과 S3 저장 → Redshift 적재
│  ├─ redshift_loader.py         Redshift Data API 적재 (트랜잭션 · 백오프 · 타임아웃)
│  └─ k8s/spark-job.yaml         ServiceAccount · 최소 권한 Role · Job (client 모드)
└─ Q8/
   ├─ k8s/01-namespace.yaml · 02-headless-service.yaml · 03-statefulset.yaml
   ├─ stock_stats.csv            과제 05 집계 결과 (load_results.sh 입력)
   └─ load_results.sh            파드별 적재 + 파드별 DNS 조회
```

## 전체 흐름

```
 stock_prices.csv ─업로드→ s3://<본인버킷>/stock/raw/
                                 │
         ┌───────────────────────┴───────────────────────┐
         │ [Q5] spark-submit process_stocks.py            │ [Q7] K8s Job: spark-submit --master k8s:// (client)
         │   clean() → aggregate() → 출력                  │   같은 clean() · aggregate() 재사용
         ▼                                                ▼
 s3://<본인버킷>/stock/silver/  (정제 데이터, parquet)   s3://<본인버킷>/stock/daily_stats/  (집계 5행, parquet)
         │ [Q6] Redshift COPY                              │ Redshift Data API: staging COPY → 본 테이블 교체 (1 트랜잭션)
         ▼                                                ▼
 Redshift stock_prices                                Redshift stock_daily_stats

 [Q8] stock_stats.csv(과제 05 집계 결과) → StatefulSet 파드 5개(종목별 1개)에 index.html 로 적재
```

## 과제 05 — `Q5/process_stocks.py`

```bash
spark-submit \
  --packages org.apache.hadoop:hadoop-aws:3.3.4,com.amazonaws:aws-java-sdk-bundle:1.12.262 \
  Q5/process_stocks.py \
  --input  s3a://<본인버킷>/stock/raw/stock_prices.csv \
  --output s3a://<본인버킷>/stock/silver/
```

| 함수 | 역할 |
|---|---|
| `RAW_SCHEMA` | raw CSV 를 문자열로 읽는 명시적 스키마 |
| `clean()` | 타입 변환 **후** `dropna()` → 원래 결측과 변환 실패를 함께 제거 → `change_type` UDF 추가 |
| `change_type` (UDF) | 상승/하락/보합. None 입력을 안전하게 처리 |
| `aggregate()` | 종목별 평균종가 · 최고가 · 최저가 · 총거래량 |

- 자격 증명 방식을 코드에 고정하지 않습니다. S3A 기본 체인이 환경 변수 → EC2 IAM Role 순으로 찾습니다.
- silver 는 과제 06 에서 COPY 로 바로 적재하므로 파티션 디렉터리 없이 저장합니다.

## 과제 07 — `Q7/`

```bash
# 01_예시답안_Q5_Q7_Q8 폴더에서 빌드 (Q5 모듈을 함께 담기 위해)
docker build -f Q7/Dockerfile -t de7-q7-spark:1.0.0 .
# k3s 노드에 이미지 넣기 (레지스트리를 쓰지 않는 경우)
docker save de7-q7-spark:1.0.0 | sudo k3s ctr images import -
# 매니페스트의 <워크그룹명>, <ACCOUNT_ID>, <Redshift COPY용 Role>, <본인버킷> 을 채운 뒤
kubectl apply -f Q7/k8s/spark-job.yaml
kubectl get job q7-spark-stock          # COMPLETIONS 1/1
kubectl logs job/q7-spark-stock
```

| 구성 요소 | 역할 |
|---|---|
| `spark_job.py` | Q5 의 `clean()` · `aggregate()` 를 import 해서 재사용 → 집계 결과(5행)를 parquet 으로 저장 → `redshift_loader` 로 적재 → `COUNT(*)` 출력 |
| `redshift_loader.py` | `CREATE TABLE IF NOT EXISTS` → `CREATE TEMP TABLE …_stage` → `COPY …_stage` → `DELETE` → `INSERT … SELECT` 를 `batch_execute_statement` 하나(=한 트랜잭션)로 실행. 상태 조회는 1→2→4→8→10초 백오프, 제한 시간 600초 |
| `k8s/spark-job.yaml` | ServiceAccount `spark` + Role(파드·서비스·configmap·PVC 관리 최소 권한) + Job. 드라이버 주소는 Downward API 의 파드 IP(`spark.driver.host=$(POD_IP)`)로 넘겨 별도 Service 가 필요 없음. `spark.kubernetes.driver.pod.name=$(POD_NAME)` 으로 executor 가 드라이버 파드에 종속되어 함께 정리됨 |
| 자격 증명 | 코드·이미지·YAML 에 키 없음. S3A · boto3 모두 EC2 인스턴스 IAM Role 사용. S3A 출력 커밋에는 Role 에 `s3:DeleteObject` 권한이 필요 |
| EC2 설정 | 파드 안에서 인스턴스 Role 을 쓰려면 인스턴스 메타데이터 **hop limit 을 2 이상**으로 설정 (기본값 1 이면 파드에서 자격 증명을 못 받음) |

client 모드 동작:
```
Job 파드 (드라이버, spark-submit)
   │  K8s API 호출 (ServiceAccount spark 의 Role 권한)
   ├──────────────► executor 파드 2개 생성
   │◄────────────── executor 가 드라이버 파드 IP 로 접속·등록
   ▼
 작업 완료 → executor 파드 자동 정리 → Job COMPLETIONS 1/1
```

## 과제 08 — `Q8/`

```bash
kubectl apply -f Q8/k8s/
kubectl rollout status statefulset/stock -n stock-honggildong
kubectl get statefulset,pod,pvc -n stock-honggildong
NS=stock-<본인이름> NAME=<본인이름> COHORT=<기수> bash Q8/load_results.sh
```

| 파일 | 핵심 |
|---|---|
| `01-namespace.yaml` | `stock-{본인이름}` |
| `02-headless-service.yaml` | `clusterIP: None` → 파드별 DNS(`stock-0.stock-svc` …), 포트 이름 `web` |
| `03-statefulset.yaml` | `serviceName: stock-svc`, `replicas: 5`, 포트 이름 `web`, `volumeClaimTemplates` + `local-path`, TCP readinessProbe(빈 볼륨에서도 Ready → DNS 생성), 리소스 요청·제한 |
| `stock_stats.csv` | 과제 05 집계 결과. 수치를 스크립트에 직접 쓰지 않음 |
| `load_results.sh` | 종목 수와 파드 수가 다르면 중단 → 파드별 `index.html` 기록 → `stock-0` 안에서 5개 DNS 조회(종목·수치·이름·기수 표시) |

```
 Headless Service stock-svc (clusterIP: None)
   ├─ stock-0.stock-svc → 파드 stock-0 ─ PVC html-stock-0 (AAPL)
   ├─ stock-1.stock-svc → 파드 stock-1 ─ PVC html-stock-1 (JNJ)
   ├─ stock-2.stock-svc → 파드 stock-2 ─ PVC html-stock-2 (JPM)
   ├─ stock-3.stock-svc → 파드 stock-3 ─ PVC html-stock-3 (TSLA)
   └─ stock-4.stock-svc → 파드 stock-4 ─ PVC html-stock-4 (XOM)
```

## 실행 검증

| 대상 | 방법 | 결과 |
|---|---|---|
| Q5 | `apache/spark:3.5.7` 에서 spark-submit (로컬 파일 입출력) | 3,760행, 집계 5종목이 제공 데이터 재계산값과 일치 |
| Q5 | 종가가 `N/A` 인 행 1개 추가 | 해당 행 제거 후 3,760행으로 정상 완료 |
| Q7 | 이미지로 로컬 실행 | 집계 parquet 5행, 컬럼 순서·타입이 Redshift DDL 과 일치 |
| Q7 | k3s 클러스터에 Job 배포 | `--master k8s://` 실행, executor 파드 2개 등록, Job `Complete 1/1`, 종료 후 executor 자동 정리 |
| Q7 | **AWS 전체 구성**: EC2(Ubuntu 22.04) + k3s, 인스턴스 IAM Role, S3, Redshift Serverless. YAML 은 자리표시자 4곳만 채워 그대로 적용 | 파드 안에서 인스턴스 Role 로 인증, S3 `stock/daily_stats/` 에 parquet 저장, Redshift COPY 후 `stock_daily_stats` 5행. 같은 Job 을 한 번 더 실행해도 5행 유지 (중복 적재 없음) |
| Q8 | k3s 클러스터에서 **문제지의 채점자 확인 절차 그대로** 실행: `kubectl apply -f Q8/k8s/` → `kubectl get pod -n stock-honggildong -w` → `kubectl get statefulset,pod,pvc -n stock-honggildong` → `bash Q8/load_results.sh` | 파드 stock-0~4 순차 생성, PVC 5개 Bound, 5개 DNS 응답이 종목별로 다르고 이름·기수 표시 |
