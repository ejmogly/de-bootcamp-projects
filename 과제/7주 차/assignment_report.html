## 공통 규약

> 아래 규약은 각 문항의 "제출물"에 따로 적지 않아도 반드시 지켜 주세요.  
> **A·C는 전 문항, B(Git)는 Q3 ~ Q10에만 적용합니다.**

### A. 실행 지문 (Run Fingerprint)
모든 캡처 이미지에 아래 세 값이 함께 보여야 합니다. 언제 · 어디서 · 어느 커밋에서 실행했는지를 남기는 용도입니다.
```bash
date && hostname && git rev-parse HEAD
```
- **터미널 캡처:** 지문을 따로 찍지 말고, `&&`로 이어 붙여 지문 출력과 명령 결과가 **한 화면에 연속으로** 나오게 합니다.
  ```bash
  date && hostname && git rev-parse HEAD && <이 문항에서 실행할 명령>
  ```
  - 예시: `date && hostname && git rev-parse HEAD && docker compose ps`
- **브라우저 캡처 (UI 등):** 터미널 창을 옆에 띄워 공통 명령을 실행한 상태로 두 창이 함께 담기도록 캡처합니다.
- **판정 기준:**
  - `git rev-parse HEAD` 값은 레포지토리에 실제로 올라간 커밋과 일치해야 합니다. (Git 요건이 없는 **Q1 · Q2는 `date && hostname`까지만**)
  - 캡처의 HEAD 값은 문항이 진행될수록 앞으로 나아가야 합니다.
  - 다른 문항/요구사항의 캡처 재사용 불가 (date 값이 달라야 함).
  - **Q3 ~ Q9 캡처의 hostname이 모두 같아야 합니다.** 한 환경에서 진행했음을 증빙합니다.

### B. Git 공통 요건 — Q3 ~ Q10에 적용
- **하나의 GitHub 레포지토리**에서 관리합니다. (이름 권장: `de{기수}-{이름}-week7`)

- 문항당 최소 1개 이상의 커밋을 남기며, 한 번에 1개 커밋으로 올리는 것은 불인정합니다.

## 공통 규약

> 아래 규약은 각 문항의 "제출물"에 따로 적지 않아도 반드시 지켜 주세요.  
> **A·C는 전 문항, B(Git)는 Q3 ~ Q10에만 적용합니다.**

### A. 실행 지문 (Run Fingerprint)
모든 캡처 이미지에 아래 세 값이 함께 보여야 합니다. 언제 · 어디서 · 어느 커밋에서 실행했는지를 남기는 용도입니다.
```bash
date && hostname && git rev-parse HEAD
```
- **터미널 캡처:** 지문을 따로 찍지 말고, `&&`로 이어 붙여 지문 출력과 명령 결과가 **한 화면에 연속으로** 나오게 합니다.
  ```bash
  date && hostname && git rev-parse HEAD && <이 문항에서 실행할 명령>
  ```
  - 예시: `date && hostname && git rev-parse HEAD && docker compose ps`
- **브라우저 캡처 (UI 등):** 터미널 창을 옆에 띄워 공통 명령을 실행한 상태로 두 창이 함께 담기도록 캡처합니다.
- **판정 기준:**
  - `git rev-parse HEAD` 값은 레포지토리에 실제로 올라간 커밋과 일치해야 합니다. (Git 요건이 없는 **Q1 · Q2는 `date && hostname`까지만**)
  - 캡처의 HEAD 값은 문항이 진행될수록 앞으로 나아가야 합니다.
  - 다른 문항/요구사항의 캡처 재사용 불가 (date 값이 달라야 함).
  - **Q3 ~ Q9 캡처의 hostname이 모두 같아야 합니다.** 한 환경에서 진행했음을 증빙합니다.

### B. Git 공통 요건 — Q3 ~ Q10에 적용
- **하나의 GitHub 레포지토리**에서 관리합니다. (이름 권장: `de{기수}-{이름}-week7`)
- **레포지토리는 반드시 Public으로 생성**합니다. (Private이면 0점)
- 레포지토리 루트에 **README.md**를 작성합니다. (본인 이름 · 기수 포함, Q10 대상)
- **레포지토리 = project/ 그 자체**입니다.
- 문항당 최소 1개 이상의 커밋을 남기며, 한 번에 1개 커밋으로 올리는 것은 불인정합니다.
- 커밋 메시지는 문항과 작업 내용을 알 수 있게 작성합니다. (예: `Q3: Airflow compose 환경 구축`)
- 각 문항 폴더에 **git_log.txt** 생성:
  ```bash
  git log -p > ../{문제번호}/git_log.txt
  ```
- **제출 ZIP의 project/ 내용과 GitHub 레포지토리 내용이 일치**해야 합니다. (.gitignore 대상 제외)
