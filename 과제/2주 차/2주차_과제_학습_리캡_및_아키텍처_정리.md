## 🏛️ 엔터프라이즈 Git-Flow 협업 및 CI/CD 거버넌스 아키텍처

```
[로컬 작업 공간]
Working Tree ──(git add)──> Staging Area ──(git commit)──> Local Repo (feature/xxx)
                                                                 │
                                                            (git push)
                                                                 │
[원격 GitHub 저장소]                                             ▼
Main (v1.0.0 프로덕션) <──────── PR Merge (Release) <────── Develop (개발 통합)
        │                                                        ▲
  (Hotfix 분기)                                                  │ (PR Merge)
        ▼                                                        │
hotfix/emergency ─────── PR Dual Merge ─────────────────> feature/etl-pipeline
```

## 💡 실무 엔지니어링 핵심 포인트
1. **Branch Protection Rules**: `main`과 `develop` 브랜치에 직접 푸시를 차단하고, 최소 2명의 승인 및 CI 파이프라인(Linting, Unit Test) 통과 필수화.
2. **Rebase 기반 선형 히스토리**: Feature 브랜치를 Develop으로 통합하기 전 `git fetch && git rebase origin/develop`을 수행하여 충돌을 로컬에서 선제 해결.
3. **Secrets Leak 방지**: `.gitignore`와 함께 `pre-commit` 훅을 구성하여 AWS Access Key, DB 패스워드 등 보안 민감 정보의 커밋을 원천 차단.
