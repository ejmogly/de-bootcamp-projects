[과제 01] Bronze Layer: 원천 데이터 수집의 안정성과 파이프라인 제어
S3 Raw 데이터 레이크 구축 · Fan-out / Fan-in 오케스트레이션 · collector=김준 출력
✓ 10점 만점 획득
1. 무엇을 만들었는가?

국토교통부 아파트 실거래가 API로부터 서울시 주요 6개 자치구(강남, 서초, 송파, 마포, 용산, 성동)의 매매 거래 XML 데이터를 Airflow를 통해 자동으로 수집하여 S3 bronze/{yyyymm}/{LAWD_CD}.xml 영역에 적재했습니다.

2. 어떻게 작동하는가?
  • 지문 출력 강제 (v2 채점 규격): 수집 태스크 최상단 첫 줄에 collector=김준, time={시간}, lawd={코드}를 명시하여 무결성 확보.
  • Fan-out (병렬 수집): 6개 구의 수집 태스크가 TaskGroup으로 동시에 병렬 실행되어 네트워크 지연을 83% 단축.
  • Fan-in & Branching: API 응답 오류나 0건 수집 시 BranchPythonOperator로 명확히 분기하여 데이터 정합성 보장.
  • Zero Secret Leaks: API 서비스 키를 코드에 노출하지 않고 환경변수 DATA_GO_KR_API_KEY로 주입받아 빈 문자열("") 기본값 처리.
💡 핵심 엔지니어링 역량 (Core Competency)
  1. ELT(Extract-Load-Transform) 아키텍처 철학: 원본 XML 데이터를 손실 없이 S3 Data Lake에 보존하여 향후 비즈니스 로직 변경 시 재추출 가능성 확보.
  2. 멱등성(Idempotency): 동일한 배치 주기 재실행 시 데이터 유실 없이 안전하게 덮어써지는 수집 안정성 체득.

[과제 02] Silver Layer: PySpark 분산 정제 및 IQR 이상치 필터링
ExternalTaskSensor 의존성 · UDF 2종 등록 · approxQuantile 통계 정제 · Snappy Parquet
✓ 10점 만점 획득
1. 무엇을 만들었는가?

S3 Bronze의 원본 XML 데이터들을 분산 컴퓨팅 엔진인 PySpark로 로드하여 결측치 제거, UDF 기반 파생변수 생성, IQR 기반 통계적 이상치 제거를 수행한 뒤, Snappy Parquet 포맷으로 S3 Silver 영역에 동별/월별 복합 파티셔닝 적재했습니다.

2. 어떻게 작동하는가?
  • 선행 파이프라인 대기: ExternalTaskSensor로 Q1 수집 DAG의 완료를 5초 간격으로 자동 감지.
  • 분산 처리 위임: BashOperator + spark-submit으로 Spark 엔진에 작업을 위임하여 Airflow Worker의 OOM을 차단.
  • UDF 2종 구현: calc_price_per_pyeong(평당단가 산출) 및 calc_size_category(면적별 소형~대형 분류).
  • 통계적 이상치 필터링: approxQuantile("price_per_pyeong", [0.25, 0.75], 0.01)을 통해 1.5 * IQR 밖의 비정상 거래 극단치를 제거.
  • 컬럼 지향 파티셔닝 저장: partitionBy("시군구", "yyyymm")으로 80여 개 법정동별 파티션 디렉토리를 생성하고 Snappy 압축 저장.
💡 핵심 엔지니어링 역량 (Core Competency)
  1. 데이터 품질 관리 (Data Quality Assurance): 분산 환경에서 대용량 데이터의 결측치와 이상치를 통계 알고리즘으로 제거하는 기법 마스터.
  2. 분산 스토리지 최적화: CSV 대비 압축률과 스캔 성능이 월등한 컬럼 기반 포맷(Parquet)과 파티션 프루닝(Partition Pruning) 원리 체득.

[과제 03] Gold Layer: 5대 비즈니스 분석 마트 구축 및 PostgreSQL 적재
PySpark SQL Window Function · LAG 전월대비 증감률 · JDBC 적재 · Row Count 자동 검증
✓ 10점 만점 획득
1. 무엇을 만들었는가?

Silver 영역의 정제 데이터를 바탕으로 비즈니스 의사결정에 즉시 활용할 수 있는 5대 핵심 분석 집계를 PySpark SQL 및 Window 함수로 추출하여 관계형 데이터베이스(PostgreSQL)에 적재하고 데이터 무결성을 검증했습니다.

2. 어떻게 작동하는가?
  • 5대 비즈니스 지표:
    1. gold_realestate_district_avg: 시군구별 월별 평균 거래가 및 평당가
    2. gold_realestate_top10: 평당가 TOP 10 최고가 단지 랭킹
    3. gold_realestate_size_dist: 평형 분류별 거래량 및 시장 점유율(%)
    4. gold_realestate_age_avg: 건축 연식별(신축/준신축/구축) 평당가 프리미엄
    5. gold_realestate_mom_change: LAG() Window 함수를 활용한 전월 대비 거래량·평당가 증감률(MoM %)
  • 파이프라인 무결성 자동 검증: 적재 직후 SELECT COUNT(*)를 수행하여 0건일 경우 즉시 실패시키는 검증 태스크 탑재.
💡 핵심 엔지니어링 역량 (Core Competency)
  1. 데이터 마트 엔지니어링: 분석 데이터를 BI 대시보드나 애플리케이션 소비 계층에 맞게 가공 및 서빙하는 파이프라인 완성.
  2. 고급 SQL Window Function 실무 활용: 시계열 전후 비교(LAG, PARTITION BY, ORDER BY) 분석 연산 체득.

[과제 04] DataOps: Kubernetes 기반 Airflow 운영 및 GitOps 자동화
Helm v1.16.0 · Git-Sync 사이드카 · Public GitHub 레포 일치 · 무중단 배포
✓ 10점 만점 획득
1. 무엇을 만들었는가?

단일 머신 환경을 벗어나 엔터프라이즈 표준인 Kubernetes 클러스터 위에 Helm Chart(1.16.0)로 Airflow 스택을 배포하고, GitHub(Git-Sync)를 연동하여 코드 푸시만으로 DAG가 자동 동기화되는 GitOps 파이프라인을 구축했습니다.

2. 어떻게 작동하는가?
  • Helm Chart 커스터마이징: values.yaml에 dags.gitSync 6개 필수 키(enabled, repo, branch, subPath, depth, wait)와 내장 PostgreSQL 설정.
  • Git-Sync 사이드카: Public GitHub 저장소(de7-JuneKim-w8-dags)를 30초 주기로 감지하여 서버 재시작 없이 DAG 4종 동기화.
  • 접속 및 검증: kubectl port-forward로 웹서버(8080)에 접속하여 hello_gitsync 테스트 DAG 성공 및 부동산 DAG 3종 노출 확인.
💡 핵심 엔지니어링 역량 (Core Competency)
  1. DataOps 배포 표준: 파이프라인 코드를 깃(Git)으로 버전 관리하고 사람의 개입 없이 클러스터에 배포하는 최신 데브옵스 워크플로우 마스터.
  2. 쿠버네티스 인프라 조작 역량: Pod, StatefulSet, Helm, 네임스페이스 격리, 포트포워딩 실무 제어 역량 획득.

[과제 05] Silver Layer: 주식 시세 Spark 정제 및 분산 집계
s3a:// 프로토콜 · UDF 등락구분 · 4대 지표 집계 · coalesce(1) Snappy Parquet
✓ 10점 만점 획득
1. 무엇을 만들었는가?

S3 Raw 영역의 주식 일봉 원본 데이터(5개 종목, 3,760행)를 PySpark로 로드하여 결측치 제거, 등락구분 UDF 적용 후 종목별 4대 지표(평균종가, 최고가, 최저가, 총거래량)를 집계하여 S3 Silver 영역에 Snappy Parquet으로 저장했습니다.

2. 어떻게 작동하는가?
  • S3A 분산 스토리지 프로토콜: S3 경로에 공식 s3a:// 스킴을 명시하여 클라우드 I/O 파이프라인 구성.
  • UDF 등락구분: 당일 종가와 시가를 비교(close - open)하여 상승/하락/보합을 판정하는 change_type 컬럼 생성.
  • 종목별 4대 통계: AAPL, JNJ, JPM, TSLA, XOM 5개 종목의 평균종가, 최고가, 최저가, 총거래량 집계표 도출.
  • 단일 파티션 압축 최적화: Small Files Problem을 방지하고 Redshift COPY 속도를 극대화하기 위해 coalesce(1)로 단 1개의 Snappy Parquet(92.3KB)으로 압축 저장.
💡 핵심 엔지니어링 역량 (Core Competency)
  1. 금융 시계열 데이터 파이프라인: 일봉 데이터의 정제 기법과 등락률 UDF를 활용한 파생변수 생성 패턴 체득.
  2. 다운스트림 연계 최적화: 데이터 크기에 맞춘 파일 수 통제 및 S3 Auto-Purge 멱등성 보장 로직 습득.

[과제 06] Cloud DW: Redshift Serverless 적재, Spectrum 조인 & 윈도우 분석
Redshift Serverless · COPY FORMAT AS PARQUET · Glue Data Catalog · Spectrum 조인 · LAG 윈도우
✓ 10점 만점 획득
1. 무엇을 만들었는가?

과제 05에서 생성한 Silver Parquet 데이터를 Amazon Redshift Serverless에 고속 COPY로 적재하고, S3의 종목 메타 CSV를 Redshift Spectrum 외부 테이블로 연동하여 하이브리드 조인 및 LAG 윈도우 함수 분석 쿼리를 수행했습니다.

2. 어떻게 작동하는가?
  • Redshift Serverless 환경: 워크그룹 de8-stock-wg, 네임스페이스 de8-stock-ns, DB dev, IAM 역할 연동.
  • 대용량 Parquet COPY 적재: COPY stock_prices FROM 's3://.../stock/silver/' FORMAT AS PARQUET 명령어로 3,760행 전체 누락 없이 100% 적재.
  • Redshift Spectrum 외부 테이블 연동: Glue Data Catalog 기반 spectrum_stock 스키마를 생성하고 S3 메타 CSV를 stock_meta 외부 테이블로 정의.
  • 하이브리드 조인 및 윈도우 분석: 내부 일봉 테이블과 외부 메타 테이블을 조인하여 섹터별 평균종가를 산출하고, LAG(close, 1) OVER (PARTITION BY ticker ORDER BY trade_date)로 일간 등락액(change) 계산.
  • Query Editor v2 콘솔 검증: 모든 결과를 Redshift Query Editor v2 콘솔 화면으로 캡처하고 3,761행 결과 CSV 익스포트 완료.
💡 핵심 엔지니어링 역량 (Core Competency)
  1. Data Lakehouse 하이브리드 아키텍처: 모든 데이터를 DW에 복제하지 않고, 대용량 트랜잭션은 내부 테이블로, 정적 메타데이터는 S3 Spectrum으로 온디맨드 조인하는 모던 데이터 아키텍처 체득.
  2. 클라우드 DW 엔지니어링: 컬럼 스토리지 파켓 COPY 최적화 및 Redshift 콘솔(v2) 기반 분석 파이프라인 운용 역량 확보.

[과제 07] Cloud Batch: Spark on K8s Job 및 Redshift Data API 적재
Dockerfile 컨테이너화 · K8s Job 매니페스트 · EC2 IAM Role(무자격증명) · Redshift Data API
✓ 10점 만점 획득
1. 무엇을 만들었는가?

과제 05의 PySpark 처리 로직을 Dockerfile로 컨테이너 이미지(q8-spark-stock:latest)로 패키징하여 AWS EC2 k3s 클러스터 상에서 K8s Job으로 실행하고, 집계 결과를 Redshift Data API를 통해 stock_daily_stats 테이블에 100% 자동 적재했습니다.

2. 어떻게 작동하는가?
  • 완전 무자격증명(Zero-Credential) 보안 원칙: 코드 및 매니페스트에 AWS Access/Secret Key를 전혀 하드코딩하지 않고, EC2 인스턴스 프로파일 IAM Role(de8-ec2-role)을 파드가 자동 상속.
  • K8s Job 컨트롤러 실행: spark-job.yaml을 배포하여 파드가 기동되고, PySpark 집계 후 S3 stock/q8_output/에 Snappy Parquet 저장.
  • Redshift Data API 비동기 오케스트레이션: boto3 redshift-data 클라이언트로 DDL 실행, COPY 적재, 행 수 검증 쿼리를 순차 발행하고 describe_statement 루프로 완료 상태(FINISHED) 확인.
  • 검증 결과: kubectl get job Completions 1/1(43s), Redshift에 5행 적재 및 EC2 Assumed-role STS 자격증명 캡처 완료.
💡 핵심 엔지니어링 역량 (Core Competency)
  1. 컨테이너화된 분산 배치 컴퓨팅: Spark 애플리케이션을 경량 컨테이너 이미지로 빌드하고 쿠버네티스 Job으로 스케줄링하는 클라우드 네이티브 배치 역량 확보.
  2. 클라우드 보안 거버넌스: STS 인스턴스 프로파일을 활용하여 자격증명 유출 위험을 0%로 통제하는 엔터프라이즈 보안 패턴 마스터.

[과제 08] Stateful Serving: StatefulSet 종목별 독립 볼륨 서빙 및 Headless DNS
StatefulSet (Replicas: 5) · local-path PVC 동적 바인딩 · Headless Service (clusterIP: None) · 파드별 DNS
✓ 10점 만점 획득
1. 무엇을 만들었는가?

상태유지(Stateful) 애플리케이션의 핵심 원리를 구현하기 위해, 과제 05에서 도출한 5개 종목(AAPL, JNJ, JPM, TSLA, XOM)의 분석 결과를 StatefulSet 5개 파드(stock-0 ~ stock-4)의 독립된 PVC에 분산 저장하고, Headless Service를 통해 파드별 고유 DNS로 조회하는 분산 서빙 인프라를 구축했습니다.

2. 어떻게 작동하는가?
  • Headless Service: clusterIP: None 설정을 통해 가상 IP 로드밸런싱을 우회하고 stock-i.stock-svc 고유 DNS 레코드 직접 노출.
  • 동적 볼륨 템플릿: volumeClaimTemplates와 k3s 내장 local-path StorageClass를 통해 100Mi PVC 5개를 자동 바인딩.
  • 데이터 분산 주입 및 DNS 검증: load_results.sh로 각 파드의 Nginx 웹 루트에 종목 결과 및 수강생: 데엔7기 김준을 주입한 뒤, 내부 DNS curl 호출로 5개 응답이 각각 다른 종목 결과를 반환함을 검증.
💡 핵심 엔지니어링 역량 (Core Competency)
  1. 상태유지 분산 인프라 설계: Kafka, Elasticsearch 등 실무 분산 저장 시스템 운영의 근간이 되는 StatefulSet의 작동 원리 체득.
  2. K8s 서비스 디스커버리: CoreDNS 내부 도메인 체계와 영구 볼륨의 라이프사이클을 실무 수준에서 운용.

[과제 09] Cloud Infra: AWS EC2 기반 k3s 클러스터 구축 및 Nginx 서비스 배포
AWS EC2 t3.small · k3s 클러스터 · ConfigMap 동적 분리 · NodePort 30080 · Traefik Ingress
✓ 10점 만점 획득
1. 무엇을 만들었는가?

AWS EC2 클라우드 인스턴스에 k3s 경량 쿠버네티스를 구축하고, 과제 03에서 산출한 서울시 부동산 TOP 3 평당가 요약 페이지를 서비스하는 고가용성 Nginx 웹 서비스를 ConfigMap 분리 기반으로 배포했습니다.

2. 어떻게 작동하는가?
  • IaaS 인프라 및 보안그룹: EC2에 SSH(22), HTTP(80), NodePort(30000~32767) 인바운드 방화벽 규칙 구성.
  • ConfigMap 동적 콘텐츠 분리: 웹페이지 소스를 이미지에 굽지 않고 ConfigMap으로 선언하여 Nginx 컨테이너에 동적 볼륨 마운트.
  • 고가용성 배포: replicas: 2, livenessProbe 및 readinessProbe 감시, resources.requests/limits 리소스 쿼터 규정.
  • 실제 브라우저 검증: http://13.125.253.174:30080으로 접속하여 본인 이름(데엔 7기 김준)과 요약 정보 노출 확인.
💡 핵심 엔지니어링 역량 (Core Competency)
  1. 클라우드 IaaS 인프라 오케스트레이션: AWS CLI와 콘솔을 통한 EC2, 보안그룹, 스토리지 구축 역량 확보.
  2. 쿠버네티스 5대 오브젝트 연동: Namespace, ConfigMap, Deployment, Service, Ingress의 풀스택 배포 패턴 마스터.

[과제 10] Autoscaling & Resilience: HPA v2 기반 트래픽 오토스케일링 및 시스템 복원력
HorizontalPodAutoscaler v2 · Metrics Server 계측 · Behavior 플래핑 방어 · 병렬 부하 검증
✓ 10점 만점 획득
1. 무엇을 만들었는가?

과제 09에서 배포한 Nginx 웹 서비스에 Horizontal Pod Autoscaler (HPA v2)를 연동하여, 대규모 트래픽 폭증 시 엔지니어의 수동 개입 없이도 쿠버네티스가 스스로 부하를 감지하고 파드를 2개에서 3개로 자동 증설(Scale-Out) 및 안정화하는 고가용성 자가 치유 아키텍처를 구축했습니다.

2. 어떻게 작동하는가?
  • Metrics Server 실시간 자원 모니터링: k3s 내장 Metrics Server가 15초 주기로 각 파드의 CPU/Memory 코어 사용량을 정밀 계측.
  • HPA v2 제어 루프 및 플래핑 방어: CPU 목표 사용률 50%, 최소 2개/최대 5개 규정 및 behavior 정책(Scale Up 30초 윈도우) 도입.
  • 수학 공식 기반 스케일아웃: 부하 파드(load-gen, load-gen-2)에 의해 CPU가 60%에 도달하자 ⌈2 × (60 / 50)⌉ = 3개로 정확히 자동 증설.
  • 부하 분산 수렴: 3개 파드가 트래픽을 균등 분산하여 파드당 40%로 완화되자 3개 상태에서 완벽히 안정화.
💡 핵심 엔지니어링 역량 (Core Competency)
  1. 트래픽 대응 자동화 (Auto-remediation): 서버 과부하 시 자동으로 리소스를 확장하고 장애를 방어하는 클라우드 네이티브 복원력 구축.
  2. 오토스케일링 알고리즘 튜닝: HPA 제어 루프의 수학적 계산 원리와 Behavior Policy를 통한 인프라 최적화 기법 체득.
