## Part 1 — 부동산 실거래가 Medallion ETL (과제 01 ~ 04)

### 과제 01 — 부동산 실거래가 Bronze (API 수집)
- **배점:** 10점
- **개요:** 국토교통부 실거래가 공개 API를 호출하여 다중 시군구의 아파트 매매 데이터를 수집하고, 원본 XML을 그대로 AWS S3 bronze 영역에 저장하는 Airflow DAG를 구현하세요. 본인이 직접 발급받은 `data.go.kr` API 키를 사용해야 합니다.

#### [조건]
1. **API 신청:** [data.go.kr 국토교통부_아파트 매매 실거래가 자료](https://www.data.go.kr/data/15126469/openapi.do)
2. **Endpoint:** `https://apis.data.go.kr/1613000/RTMSDataSvcAptTrade/getRTMSDataSvcAptTrade`
3. **필수 파라미터:** `serviceKey`, `LAWD_CD` (시군구코드 5자리), `DEAL_YMD` (yyyyMM)
4. **DAG 이름:** `bronze_realestate_collect`
5. **스케줄:** `@monthly`, `catchup=True` (월 단위)
6. **병렬 수집:** `TaskGroup` 또는 `Dynamic Task Mapping(expand)`으로 6개 시군구 병렬 수집
   - 대상 시군구코드: `11680` (강남구), `11650` (서초구), `11710` (송파구), `11440` (마포구), `11170` (용산구), `11200` (성동구)
7. **분기 처리:** `BranchPythonOperator`로 응답 0건 / XML 파싱 실패 시 분기 처리
8. **S3 저장 경로:** `s3://realestate-{본인이름}/bronze/{yyyymm}/{LAWD_CD}.xml`
9. **지문 출력 강제:** 수집 task 첫 줄에 아래 코드 반드시 삽입  
   `print(f"collector={본인이름}, time={datetime.now()}, lawd={LAWD_CD}")`

#### [제출물]
- `Q1/dags/bronze_realestate_collect.py`
- `Q1/capture/airflow_graph.png` — TaskGroup 그래프 (6개 task 병렬 가시화)
- `Q1/capture/s3_objects.png` — AWS S3 콘솔에서 저장된 6개 객체 확인 화면

#### [채점 기준]
- `TaskGroup` 또는 `expand` (dynamic task mapping) 구현 여부
- `BranchPythonOperator` 분기 로직 존재 여부
- `boto3.put_object` 또는 `S3Hook.load_string` 사용
- `data.go.kr` API URL 호출 정합성
- `capture/airflow_graph.png` 및 `capture/s3_objects.png` 존재
- **(v2) 수집 task 첫 줄 `collector={본인이름}` print 출력 (코드 또는 Task 로그 캡처에서 본인 이름 노출 필수)**

#### [❌ 0점 및 감점 판정 사례]
- `TaskGroup`/`dynamic task mapping` 없이 6개 시군구를 순차 task로 하드코딩한 경우
- `BranchPythonOperator` 없이 항상 성공 경로만 존재하는 경우 (실패 분기 누락)
- S3에 저장하지 않고 로컬 파일시스템에만 저장한 경우
- `collector={본인이름}` print 누락으로 코드/로그 어디에도 본인 이름이 확인되지 않는 경우
- 캡처 누락 또는 다른 DAG 캡처 재사용 시

### 과제 02 — 부동산 실거래가 Silver (PySpark 정제 + UDF)
- **배점:** 10점
- **개요:** 과제 01에서 S3 Bronze에 수집된 원본 XML을 읽어 결측치 제거, UDF 기반 컬럼 파생, IQR 이상치 필터링을 거쳐 Silver 영역에 Parquet 형식으로 저장하는 Spark 변환 DAG를 작성하세요.

#### [조건]
1. **DAG 이름:** `silver_realestate_transform`
2. **선행 대기:** `ExternalTaskSensor`로 과제 01 DAG(`bronze_realestate_collect`)의 성공 완료 대기
3. **Spark Job 실행:** `SparkSubmitOperator` 또는 `BashOperator` + `spark-submit`으로 실행 (**`PythonOperator` + `python` 실행 금지**)
4. **SparkApplication Name:** Spark UI 우상단 Application Name이 반드시 `silver_realestate_transform`이어야 함
5. **정제 및 UDF 변환:**
   - XML 파싱 후 결측치(`거래금액`, `전용면적`) 제거
   - `거래금액` 쉼표 제거 후 정수형 캐스팅, `전용면적` 실수형 변환
   - `계약년`, `계약월`, `계약일` 조합하여 `deal_date` (`yyyy-MM-dd`) 파생
   - **UDF (1) `price_per_pyeong`:** `거래금액 / (전용면적 / 3.30578)` 평당단가 계산 (만원 단위)
   - **UDF (2) `size_category`:** 전용면적 기준 크기 분류
     - `60㎡ 미만`: 소형
     - `60㎡ 이상 ~ 85㎡ 미만`: 중소형
     - `85㎡ 이상 ~ 135㎡ 미만`: 중대형
     - `135㎡ 이상`: 대형
6. **이상치 필터링:** `approxQuantile` 또는 `percentile_approx` 함수를 활용한 IQR 기반 평당단가 극단치(상·하위 1.5 * IQR) 제거
7. **출력 및 저장:**
   - 포맷: Parquet (`snappy` 압축)
   - 파티션 키: `(시군구, yyyymm)`
   - S3 경로: `s3://realestate-{본인이름}/silver/`

#### [제출물]
- `Q2/dags/silver_realestate_transform.py`
- `Q2/scripts/silver_spark.py`
- `Q2/capture/spark_ui.png` — Spark UI (4040 포트) Application Name(`silver_realestate_transform`) 및 Job 실행 화면
- `Q2/capture/s3_silver.png` — S3 silver 디렉토리의 파티션 폴더 및 `part-*.snappy.parquet` 확인 화면

#### [채점 기준]
- `ExternalTaskSensor` 의존성 구성
- `SparkSubmitOperator` 또는 `BashOperator + spark-submit` 사용 여부
- UDF 등록 2회 이상 (`@udf` 또는 `udf()` 호출)
- IQR 이상치 계산 로직 (`approxQuantile` 또는 `percentile_approx`)
- `write.parquet` + `compression="snappy"` + `partitionBy` 적용
- `capture/spark_ui.png` 및 `capture/s3_silver.png` 존재

#### [❌ 0점 및 감점 판정 사례]
- `spark_ui.png` 우상단 Application Name이 `silver_realestate_transform`이 아닌 경우 (타 문항 캡처 재사용)
- UDF 등록 없이 일반 컬럼 연산(산술식)만으로 파생한 경우
- IQR 이상치 제거 없이 원본 데이터를 그대로 저장한 경우
- Parquet이 아닌 CSV 등으로 저장하거나 압축/파티션 미적용 시

### 과제 03 — 부동산 실거래가 Gold (집계 + PostgreSQL 적재)
- **배점:** 10점
- **개요:** 과제 02의 Silver Parquet 데이터를 입력으로 5종 집계를 수행하고, 그 결과를 로컬 PostgreSQL의 5개 Gold 테이블에 적재하세요.

#### [조건]
1. **DAG 이름:** `gold_realestate_aggregate`
2. **선행 대기:** `ExternalTaskSensor`로 과제 02 DAG(`silver_realestate_transform`) 완료 대기
3. **Spark Job 실행:** `SparkSubmitOperator` 또는 `BashOperator + spark-submit` 사용 (**`PythonOperator + python` 금지**)
4. **5종 집계 로직 (PySpark SQL 또는 DataFrame API):**
   - **(1) `gold_realestate_district_avg`:** 시군구별 월별 평균 거래가 및 평당가
   - **(2) `gold_realestate_top10`:** 평당가 TOP 10 단지 (동, 아파트명, 평당가)
   - **(3) `gold_realestate_size_dist`:** 평형 분류(`size_category`)별 거래량 분포
   - **(4) `gold_realestate_age_avg`:** 건축연식 카테고리별 평당가 (`신축 0~5년` / `준신축 6~15년` / `구축 16년 이상`)
   - **(5) `gold_realestate_mom_change`:** 전월 대비 거래량 및 평당가 변화율 (**`LAG` 윈도우 함수 사용 필수**)
5. **PostgreSQL 적재:** `write.jdbc` 또는 `PostgresHook` (`insert_rows`) 활용
6. **적재 검증 Task:** 각 테이블의 Row Count > 0 검증

#### [제출물]
- `Q3/dags/gold_realestate_aggregate.py`
- `Q3/scripts/gold_spark_sql.py`
- `Q3/capture/postgres_tables.png` — `psql \dt` 출력 (5개 `gold_*` 테이블 노출)
- `Q3/capture/postgres_select.png` — 5개 테이블 각각 `SELECT * LIMIT 5;` 실행 결과 (한 장에 종합)

#### [채점 기준]
- `ExternalTaskSensor` 연동
- `SparkSubmitOperator` 또는 `BashOperator + spark-submit` 사용
- 5종 집계 코드 및 Window function(`LAG ... OVER`) 구현
- PostgreSQL 적재(`write.jdbc` 또는 `PostgresHook`)
- 5개 테이블명 정확도: `district_avg`, `top10`, `size_dist`, `age_avg`, `mom_change`

### 과제 06 — Redshift 적재 + Spectrum 조인 + 윈도우 분석
- **배점:** 10점
- **개요:** 과제 05의 Silver Parquet 데이터를 Amazon Redshift Serverless에 COPY로 적재하고, S3에 둔 메타데이터를 Redshift Spectrum 외부 테이블로 연동하여 조인 및 윈도우 함수 분석 쿼리를 수행하세요.

#### [조건]

   - `stock_prices` 테이블 생성 후 S3 Silver Parquet 데이터를 `COPY` 명령어로 적재

   - (**INSERT 하드코딩 절대 금지**)
3. **Spectrum 외부 테이블 연동 (`create_external.sql`):**
   - 외부 스키마(`EXTERNAL SCHEMA`) 생성
