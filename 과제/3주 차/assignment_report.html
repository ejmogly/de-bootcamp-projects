문항 06. Amazon Athena 쿼리 가속 및 비용 절감
배점: 10점 | 100% 정답
문제: Amazon Athena로 S3의 데이터를 쿼리할 때, 성능을 최적화하고 비용을 절감하는 가장 효과적인 방법은 무엇인가요?
1 (1) 모든 데이터를 하나의 거대한 JSON 파일로 저장합니다.
2 (2) 모든 데이터를 S3 Standard-IA 스토리지 클래스에 저장합니다.
3 (3) 데이터를 날짜/지역 등으로 파티셔닝하고 Parquet같은 컬럼 기반 포맷으로 변환하여 저장합니다. (선택한 정답)
4 (4) 데이터를 압축하지 않고 CSV 파일로 저장합니다.
💡 엔지니어링 분석 및 아키텍처 원리
Athena는 스캔된 데이터 용량(TB당 $5.00)을 기준으로 과금됩니다. 따라서 (1) year/month/day 파티셔닝을 통해 조건절 쿼리 시 불필요한 파티션 디렉토리를 완전히 배제(Partition Pruning)하고, (2) 컬럼 기반 포맷인 Apache Parquet을 적용하여 쿼리에서 요청한 컬럼 데이터만 선별 스캔하며, (3) Snappy 압축을 결합함으로써 스캔 바이트 수를 85%~90% 절감하여 응답 속도와 비용을 획기적으로 개선합니다. 
-- Athena 실습: Partition Projection 기반 DDL 생성 (Crawler 비용 제거 및 쿼리 가속)
CREATE EXTERNAL TABLE IF NOT EXISTS ecommerce_lakehouse.orders_partition_projection (
    order_id string,
    customer_id string,
    order_status string,
    order_amount double
)
PARTITIONED BY (order_date string)
ROW FORMAT SERDE 'org.apache.hadoop.hive.ql.io.parquet.serde.ParquetHiveSerDe'
STORED AS INPUTFORMAT 'org.apache.hadoop.hive.ql.io.parquet.MapredParquetInputFormat'
OUTPUTFORMAT 'org.apache.hadoop.hive.ql.io.parquet.MapredParquetOutputFormat'
LOCATION 's3://de-bootcamp-ecommerce-lakehouse/silver/orders/'
TBLPROPERTIES (
    'projection.enabled' = 'true',
    'projection.order_date.type' = 'date',
    'projection.order_date.range' = '2025-01-01,NOW',
    'projection.order_date.format' = 'yyyy-MM-dd',
    'storage.location.template' = 's3://de-bootcamp-ecommerce-lakehouse/silver/orders/dt=${order_date}'
);

Redshift Spectrum은 수천 개의 AWS 관리형 Spectrum 처리 노드를 활용하여 S3에 저장된 대용량 오픈 포맷(Parquet, ORC, CSV) 데이터를 Redshift 내부 고속 SSD 로컬 테이블과 직접 조인할 수 있는 Zero-ETL 쿼리 엔진입니다. 데이터 이동 및 중복 로드 없이 페타바이트 규모의 레이크하우스 아키텍처를 구현하는 핵심 기술입니다. 
-- Redshift Spectrum 외부 스키마 생성 및 S3 데이터 레이크 즉시 조인 쿼리
CREATE EXTERNAL SCHEMA ext_s3_lakehouse
FROM DATA CATALOG
DATABASE 'ecommerce_lakehouse'
IAM_ROLE 'arn:aws:iam::123456789012:role/RedshiftSpectrumRole'
CREATE EXTERNAL DATABASE IF NOT EXISTS;

-- 로컬 DW 고속 테이블(dim_customer)과 S3 외부 대용량 로그(fact_clickstream)의 Zero-ETL 조인
SELECT 
    c.customer_segment,
    COUNT(s.event_id) AS total_clicks,
    SUM(s.dwell_time_sec) AS total_engagement_sec
FROM redshift_dw.dim_customer c
JOIN ext_s3_lakehouse.fact_clickstream s ON c.customer_id = s.user_id
WHERE s.event_date >= '2025-01-01'
GROUP BY 1 ORDER BY 2 DESC;

문제: 데이터를 시각화하고, 대화형 대시보드를 구축하여 비즈니스 통찰력을 얻을 수 있도록 도와주는 AWS의 비즈니스 인텔리전스 (BI) 서비스는 무엇인가요?
1 (1) Amazon S3
2 (2) Amazon Athena
3 (3) Amazon QuickSight (선택한 정답)
4 (4) AWS Glue
💡 엔지니어링 분석 및 아키텍처 원리
Amazon QuickSight는 완전관리형 클라우드 기반 엔터프라이즈 BI 및 대시보드 서비스입니다. 초고속 병렬 인메모리 연산 엔진인 SPICE(Super-fast, Parallel, In-memory Calculation Engine)를 탑재하여 수백만 명의 사용자가 동시에 접근해도 Redshift나 Athena 원천 DW에 쿼리 부하를 주지 않고 서브초(Sub-second) 대화형 시각화를 제공합니다.
문항 10. Elastic IP (탄력적 IP)와 고정 공인 IP
배점: 10점 | 100% 정답
문제: EC2 인스턴스에 고정된 공인 IP 주소가 필요합니다. 인스턴스를 중지했다가 다시 시작해도 IP 주소가 변경되지 않도록 하려면 어떤 서비스를 사용해야 하나요?
1 (1) EBS (Elastic Block Store)
2 (2) Elastic IP (탄력적 IP) (선택한 정답)
3 (3) AMI
4 (4) Security Group (보안 그룹)
💡 엔지니어링 분석 및 아키텍처 원리
일반적인 EC2 퍼블릭 IP는 인스턴스가 중지(Stop)되면 AWS 공용 풀로 반환되어 재시작 시 새로운 IP가 임의 할당됩니다. 반면 Elastic IP(EIP)는 계정에 영구적으로 예약된 고정 IPv4 주소로, 인스턴스 라이프사이클과 독립적으로 유지됩니다. 외부 데이터 벤더의 방화벽 화이트리스트 등록이나 고정 엔드포인트 수집 노드 운영 시 반드시 EIP를 할당해야 연결 단절을 방지할 수 있습니다.
