## 🏛️ 엔터프라이즈 Docker 컨테이너 가상화 아키텍처

```
[Host OS (호스트 머신)]
  ├── Docker CLI (Client) ──(REST API Socket)──> Docker Daemon (dockerd / containerd)
  │                                                    │
  ├── Port Mapping (-p 8080:8080) ────────────────────┤
  │                                                    ▼
  ├── Storage Layers:                          [Data Pipeline Containers]
  │     ├── Named Volume (/var/lib/docker/...) ──> Container 1: FastAPI Serving (/data)
  │     ├── Bind Mount (~/docker_bind) ──────────> Container 2: Batch Processor (/logs)
  │     └── Tmpfs Mount (Host RAM) ──────────────> Container 3: In-Memory Cache (/tmp)
```

## 💡 실무 엔지니어링 핵심 포인트
1. **Dockerfile 레이어 캐싱 원칙**: 자주 바뀌지 않는 `requirements.txt` 복사 및 `RUN pip install`을 먼저 실행하고, 빈번히 수정되는 애플리케이션 코드는 나중에 복사하여 빌드 시간 80% 단축.
2. **영속성 스토리지 분리(Stateful vs Stateless)**: 데이터베이스 및 영구 로그 파일은 Named Volume에 격리하여 컨테이너 재시작 및 장애 크래시 시에도 데이터 영구 보존.
3. **Slim 베이스 이미지 표준화**: 무거운 기본 우분투 이미지 대신 `python:3.11-slim`을 적용하여 보안 취약점 면적을 75% 축소하고 빌드/배포 속도 극대화.
