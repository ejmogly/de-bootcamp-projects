1. 도메인과 비즈니스 목적

📌 다루고자 하는 서비스 도메인

도심형 즉시 배송(15~30분 마이크로 풀필먼트)을 지원하는 스마트 퀵커머스 플랫폼입니다. 고객의 주문 생성, 결제 승인/부분 환불/철회, 라이더 배차 및 최종 배송 완료까지의 라이프사이클을 실시간으로 추적합니다.

🎯 이 데이터로 확인하고 싶은 핵심 가치
  • 주문 취소 및 결제 철회 감사 추적: 원천 DB에서 취소된 결제가 물리 삭제(DELETE)되더라도 Bronze 불변 로그를 통해 누수 없는 정산 대사 보장
  • 실시간 배송 SLA 준수율 모니터링: 배차 후 배송 완료까지의 리드타임 지연 및 취소율을 실시간 감지하여 라이더 보상 기준 산출

2. 테이블 구조와 관계 (ERD)

원천 PostgreSQL에 배치할 핵심 3개 엔티티입니다. orders를 중심 Hub로 하여 결제 트랜잭션과 물류 배송 정보가 1:N / 1:1로 유기적으로 연계됩니다.

테이블명 한 행의 비즈니스 의미 PK / FK 주요 컬럼 및 CDC 변경 유형
ecommerce.orders 고객 1건의 주문 마스터 헤더 PK: order_id customer_id, order_status, total_amount, ordered_at
[CDC] INSERT, UPDATE (상태 전이)
ecommerce.payments 주문에 대한 결제 승인/부분환불/철회 PK: payment_id
FK: order_id		 payment_method, pay_amount, payment_status, paid_at
[CDC] INSERT, UPDATE(금액정정), DELETE(철회)
ecommerce.deliveries 라이더 배차 및 실시간 배송 이동 상태 PK: delivery_id
FK: order_id		 rider_id, delivery_status, tracking_number, delivered_at
[CDC] INSERT, UPDATE (배송완료 등)

3. PostgreSQL 원천 테이블 생성 (DDL 및 실행 검증)

개인 PostgreSQL(source-db) 컨테이너의 app 데이터베이스에 ecommerce 스키마를 구성하고 3개 테이블을 실제 생성 및 검증했습니다.

-- 1. 전용 스키마 생성 및 초기화
CREATE SCHEMA IF NOT EXISTS ecommerce;

-- 2. 주문 테이블
CREATE TABLE ecommerce.orders (
    order_id VARCHAR(36) PRIMARY KEY,
    customer_id VARCHAR(36) NOT NULL,
    order_status VARCHAR(20) NOT NULL DEFAULT 'CREATED',
    total_amount NUMERIC(12, 2) NOT NULL CHECK (total_amount >= 0),
    delivery_address TEXT NOT NULL,
    ordered_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- 3. 결제 트랜잭션 테이블 (주문과 1:N 관계)
CREATE TABLE ecommerce.payments (
    payment_id VARCHAR(36) PRIMARY KEY,
    order_id VARCHAR(36) NOT NULL REFERENCES ecommerce.orders(order_id) ON DELETE CASCADE,
    payment_method VARCHAR(20) NOT NULL,
    pay_amount NUMERIC(12, 2) NOT NULL CHECK (pay_amount >= 0),
    payment_status VARCHAR(20) NOT NULL DEFAULT 'AUTHORIZED',
    paid_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- 4. 배송 추적 테이블 (주문과 1:1 관계)
CREATE TABLE ecommerce.deliveries (
    delivery_id VARCHAR(36) PRIMARY KEY,
    order_id VARCHAR(36) NOT NULL REFERENCES ecommerce.orders(order_id) ON DELETE CASCADE,
    rider_id VARCHAR(36),
    delivery_status VARCHAR(20) NOT NULL DEFAULT 'ASSIGNED',
    tracking_number VARCHAR(50),
    dispatched_at TIMESTAMPTZ,
    delivered_at TIMESTAMPTZ
);

-- ★ 5. Debezium UPDATE/DELETE 시 before 이미지 온전 캡처를 위한 필수 설정
ALTER TABLE ecommerce.orders REPLICA IDENTITY FULL;
ALTER TABLE ecommerce.payments REPLICA IDENTITY FULL;
ALTER TABLE ecommerce.deliveries REPLICA IDENTITY FULL;

4. 변경 시나리오 (수정·삭제 케이스)

시나리오 1: 품절로 인한 결제 금액 정정 및 결제 철회 (UPDATE & DELETE)

• 발생 상황: 45,000원 결제 후 일부 품목 품절로 38,000원으로 UPDATE ➔ 이후 고객의 즉시 주문 취소로 결제 레코드가 Hard DELETE됨.
• 수집 후 확인 목적: 원천 DB에는 0행으로 사라지지만, Bronze에 c(45,000) -> u(38,000) -> d(before=38,000)의 변경 이력이 보존되어 PG사 정산 수수료 대사 및 환불 정당성을 역추적.

시나리오 2: 라이더 배차 및 배송 상태 전이 (UPDATE status)

• 발생 상황: 배송 상태가 ASSIGNED(배차) ➔ PICKED_UP(픽업) ➔ IN_TRANSIT(배송중) ➔ DELIVERED(완료)로 전이.
• 수집 후 확인 목적: 각 상태 전이 시점(Kafka timestamp vs Flink ingested_at)을 실측하여 30분 초과 배송 건에 대한 실시간 알림 및 라이더 인센티브 페널티 자동 산출.

5. 대략적인 파이프라인 설계 (End-to-End Architecture)

원천 PostgreSQL WAL 스트림부터 Apache Iceberg Medallion 계층(Bronze·Silver·Gold)으로 이어지는 실시간 파이프라인 아키텍처입니다.

계층 (파이프라인 구간) 담당 역할 및 책임 기술적 고민 포인트 및 해결 방안
원천 ➔ Kafka (Debezium) 트랜잭션 WAL을 캡처하여 토픽별 이벤트 스트림 발행 [순서 보장] order_id를 카프카 메시지 Key로 지정하여 동일 주문 건은 항상 단일 파티션에 인입되도록 보장
Kafka ➔ Bronze (Flink) 원문(raw) 보존 및 Iceberg 테이블에 스트리밍 Append [Tombstone 처리] WHERE payload IS NOT NULL로 널 크래시 방지 및 10초 Checkpoint 단위 파일 커밋
Bronze ➔ Silver (Spark) c/u/d 변경 이력을 병합(MERGE)하여 현재 최신 상태 유지 [DELETE 반영] 비즈니스 분석 정합성을 위해 물리 삭제 대신 is_deleted = TRUE의 논리 삭제(Soft Delete) 적용
Silver ➔ Gold (dbt) 비즈니스 집계 지표 및 정산 마트 모델 빌드 [실시간 vs 비용] 일간 배치와 준실시간 마이크로 배치를 분리하여 운영 리포트 구축
📊 3회차 Flink ➔ Iceberg Bronze 적재 실측 검증 (개인 랩 실행 확인)

• 지연 시간 실측 (measure-latency.sh): 원천 결제 INSERT 커밋 확인(t1) 후 Spark Bronze 첫 조회 관찰(t2)까지 6.56초 소요 확인.
• Iceberg 메타데이터 검증: Flink Checkpoint 완료 후 MinIO S3에 신규 스냅샷이 생성되고, metadata.json -> manifest-list -> manifest file -> parquet 계층이 원자적으로 갱신됨을 실측으로 증명함.
